# ADR-002 — Supabase를 Auth + PM DB로만 사용

- **상태**: Accepted
- **일자**: 2026-04-15
- **관련**: ADR-001, URD v0.2

## 맥락
ADR-001로 재무 데이터를 로컬에 격리하였으나, 로그인·세션·프로젝트 관리(PM) 기능까지 자체 구현할 경우 개발 공수(주 5시간 × 18주)를 초과한다. OAuth·JWT·이메일 검증 등의 보안 민감 코드를 직접 작성하는 것은 리스크가 크다.

## 결정
Supabase를 두 가지 용도로만 사용한다:
1. **Auth** — 이메일/비밀번호 + OTP, JWT 발급 (JWKS 공개)
2. **PM DB** — `pm_projects`, `pm_milestones`, `pm_tasks`, `pm_task_comments` (RLS로 격리)

Supabase에는 **금액·카테고리·거래·공제** 등 재무 정보를 일체 저장하지 않는다.

## 결과
**긍정**
- 인증 구현 비용 0, JWKS 기반 표준 검증
- PM 데이터는 타 기기에서도 열람 가능 (단일 사용자이나 모바일/PC 동기화 유효)
- Free Tier 내에서 운영 (월 0원)

**부정 / 비용**
- Beelink API가 Supabase 다운 시 신규 로그인 불가 → 읽기 전용 모드 필요
- 두 DB 간 논리 FK만 있어 조인 불가 → 애플리케이션 레이어 조인

## 대안
1. **자체 Auth 서버**: 공수·보안 리스크 과다.
2. **Auth0 / Clerk**: 비용 초과 (무료 한도 MAU 너무 낮거나 기능 제한).
3. **Supabase에 재무 데이터도 저장**: ADR-001 위배.
